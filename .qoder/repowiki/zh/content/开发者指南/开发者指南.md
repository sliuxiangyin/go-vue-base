## 简介

本指南旨在为新贡献者提供完整的本地开发环境搭建流程。项目采用 Go Fiber 作为后端框架，Vue 3 + TypeScript 作为前端技术栈，支持前后端一体化开发与热重载。通过 `just` 命令可简化开发与构建流程。

## 开发环境准备

### 前置依赖安装

请确保安装以下软件及其最低版本：

- **Go 1.24+**：后端运行环境  
  安装方式：[https://go.dev/dl/](https://go.dev/dl/)
- **Node.js 16+**：前端运行环境  
  安装方式：[https://nodejs.org/](https://nodejs.org/)
- **pnpm**：推荐的前端包管理工具  
  安装命令：
  ```bash
  npm install -g pnpm
  ```

### 环境验证

安装完成后，验证版本：
```bash
go version
node --version
pnpm --version
```

## 开发服务器启动

### 推荐方式：使用 Just 命令

```bash
just dev
```

该命令会自动启动后端服务并代理前端开发服务器。

### 手动启动方式

```bash
go run -tags dev main.go
```

#### 预期输出日志

启动成功后，控制台将显示：
```
Starting web development server...
web development server started successfully
Server starting on port 8080...
```

前端开发服务器通常运行在 `http://localhost:5173`，而后端服务监听 `http://localhost:8080`。所有非 API 请求将被代理至前端服务器，因此可通过 `http://localhost:8080` 访问应用。

## 代码调试配置

### Go 端调试（使用 Delve）

1. 安装 Delve 调试器：
   ```bash
   go install github.com/go-delve/delve/cmd/dlv@latest
   ```

2. 在支持调试的 IDE（如 VS Code、GoLand）中配置启动命令：
   ```json
   {
     "mode": "debug",
     "program": "${workspaceFolder}/main.go",
     "args": ["-tags", "dev"]
   }
   ```

3. 设置断点并启动调试会话。

### Vue 前端源码映射

项目使用 Vite 构建，已默认启用 source map。在浏览器开发者工具中：

- 打开 `Sources` 面板
- 可直接查看 `.vue` 和 `.ts` 源文件
- 支持在源码中设置断点进行调试

确保 `vite.config.ts` 中包含：
```ts
build: {
  sourcemap: true
}
```

## 测试策略

### 单元测试

项目使用 Go 内置 `testing` 包进行单元测试。示例文件位于：
- `internal/app/tools/business/relationship/service_test.go`

运行测试命令：
```bash
go test ./internal/app/tools/business/relationship/service_test.go
```

测试内容包括：
- 数据库连接初始化
- AI 服务调用
- 业务逻辑验证

### 集成测试规范

1. 测试文件命名以 `_test.go` 结尾，与被测文件同目录。
2. 使用 `TestXxx` 函数命名格式。
3. 避免依赖外部网络服务，必要时使用 mock。
4. 数据库测试使用独立的测试数据库路径。

## 代码提交规范

### 分支管理

采用简化 Git Flow：
- `main`：主分支，仅用于发布
- `dev`：开发分支，日常开发基于此分支
- 功能分支：`feature/功能名`、`fix/问题描述`

### 提交信息格式

采用 Conventional Commits 规范：
```
<type>: <subject>
```

常见类型：
- `feat`：新功能
- `fix`：Bug 修复
- `docs`：文档更新
- `style`：代码格式调整
- `refactor`：重构
- `test`：测试相关
- `chore`：构建或工具变更

示例：
```
feat(database): add relationship analysis API
fix(auth): prevent nil pointer in login handler
```

### PR 审查流程

1. 提交 PR 至 `dev` 分支
2. 至少一名核心成员审查代码
3. 通过 CI 检查（如存在）
4. 合并前需解决所有评论
5. 自动合并至 `main` 并发布
