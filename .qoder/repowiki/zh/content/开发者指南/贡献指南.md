## 简介
本项目是一个使用 GoFiber 作为后端、Vue 3 + TypeScript 作为前端的全栈应用，旨在通过 AI 技术增强数据库操作体验。项目采用模块化设计，后端核心逻辑位于 `internal/app/tools` 目录下，前端界面基于组件化架构构建于 `web/src` 目录中。为确保代码质量和协作效率，特制定本贡献指南，帮助潜在贡献者了解如何有效参与项目开发。

## 分支管理策略
本项目采用标准的 Git 分支管理模型，`main` 分支作为主干分支，用于存放稳定可发布的代码。所有新功能开发应在 `feature/*` 命名空间下的特性分支上进行，例如 `feature/user-authentication` 或 `feature/database-ai-integration`。开发完成后，通过 Pull Request 合并至 `main` 分支。修复紧急问题可使用 `hotfix/*` 分支，而 `dev` 构建标签用于标识开发版本。此策略确保了主分支的稳定性，并支持并行开发多个功能模块。

## 代码提交规范
我们推荐使用 Conventional Commits 规范来编写提交信息，以提高版本历史的可读性和自动化生成变更日志的能力。提交信息应以类型前缀开头，如 `feat:` 表示新增功能，`fix:` 表示缺陷修复，`docs:` 表示文档更新，`style:` 表示代码格式调整，`refactor:` 表示重构，`test:` 表示测试相关更改，`chore:` 表示构建或辅助工具变动。前缀后紧跟冒号和空格，然后是简明扼要的描述。例如：`feat: 添加数据库关系图谱功能` 或 `fix: 修复登录验证逻辑错误`。

## Pull Request 流程
创建 Pull Request（PR）是将代码变更集成到主分支的标准方式。贡献者应在完成特性分支开发并通过本地测试后，从该分支发起 PR 至 `main` 分支。PR 应包含清晰的标题和详细描述，说明变更目的、实现方式及影响范围。建议附上截图或使用示例以帮助审查者理解改动。提交 PR 后，CI 系统将自动运行测试套件和代码检查，确保变更不会破坏现有功能。只有在 CI 通过且至少一位核心成员批准后，PR 才能被合并。

## 代码审查期望
代码审查是保证代码质量的关键环节。我们期望所有 PR 都能遵循项目既定的编码风格，保持一致性。Go 代码应符合 Go 语言最佳实践，使用 `gofmt` 格式化，变量命名清晰，函数职责单一。前端代码需遵守 Vue 3 Composition API 规范，TypeScript 类型定义准确。此外，任何功能变更都应配有相应的单元测试或集成测试，确保覆盖率不低于现有水平。文档（包括 README 和 API 注释）也应及时更新以反映最新状态。审查过程中鼓励建设性反馈和知识共享。

## 大型变更前的讨论
对于涉及架构调整、重大功能重构或引入新依赖的大型变更，我们强烈建议贡献者在开始编码前先通过 Issue 进行公开讨论。这有助于确保变更方向与项目长期目标一致，避免重复工作，并收集来自社区的宝贵意见。在 Issue 中应详细阐述提案背景、设计方案、预期收益及潜在风险。核心团队将参与讨论并提供指导，必要时可达成共识后形成正式的设计文档（RFC）。这种前置沟通机制能显著提升开发效率和最终成果质量。

## 架构与编码规范
项目遵循清晰的分层架构：`internal/app/tools` 包含业务逻辑处理，`internal/infra` 负责基础设施集成（如数据库、AI 服务），`internal/shared` 定义共享接口。Go 代码采用依赖注入模式，在 `boot.go` 中完成服务初始化与装配。API 路由通过 `routes.go` 统一注册，确保扩展性。数据库操作基于 GORM 实现，配置管理使用 `config.go` 加载环境变量。前端组件遵循 Atomic Design 原则，存放于 `web/src/components/ui`。贡献者应严格遵守这些架构约定，确保新增代码能无缝集成，维护整体系统的一致性和可维护性。
